# Contributing

Propose a focused issue or pull request describing the problem, evidence and intended user outcome. This project welcomes architecture guidance, GCP updates, profile improvements, clearer examples and packaging fixes.

Read [development](docs/development.md), run validation and tests, and include relevant results in the PR. Use synthetic examples. Do not contribute credentials, customer records, proprietary architecture, restricted audit evidence or material nonpublic information.

Preserve these distinctions: evidence versus inference; unknown versus absent; a recommendation versus a binding obligation; general context versus optional profiles; engineering risk versus legal materiality. Cite primary sources for changing legal/vendor claims with access date and applicability. Do not copy external standards or third-party skill implementations without compatible permission, attribution and license review.

Keep GCP the default preference, while honoring an engagement's actual environment and viable existing investments. Explain benefits and tradeoffs rather than mandating fashionable technology. Avoid broad new dependencies or always-loaded references without a concrete use case.

When changing installation or build behavior, test failure/rollback and exclusion boundaries. When changing assessment behavior materially, use an independent synthetic evaluation where available and report its limits. Do not claim production assurance from structural tests.

Contributions are submitted under the repository's [MIT license](LICENSE). External linked sources retain their own terms. Maintainers review changes before release.
