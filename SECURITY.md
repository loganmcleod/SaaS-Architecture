# Reporting a security issue

Do not put secrets, private customer data or exploitable sensitive details into a public issue. Use GitHub's private vulnerability reporting if the repository's Security tab offers it. Otherwise arrange a private channel with the repository owner before sharing details; do not assume private reporting is enabled.

For ordinary bugs without sensitive details, use an issue. There is no promised response SLA. Include affected version, minimal synthetic reproduction, impact and suggested mitigation where possible.

The package is advisory text plus local packaging tools. Treat contributed instructions and downloaded releases as code to review. Install only from a trusted source and verify release checksums. The installer does not require administrator privileges, obtain credentials or access cloud accounts. Assessment guidance does not grant permission for production changes or external disclosures.

The maintainer targets the latest released version for fixes. There are no production security, audit or regulatory certifications implied by this project.
